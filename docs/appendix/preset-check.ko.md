# 부록: 실행 중인 세션에서 프리셋 확인하기

[English](preset-check.md) | 한국어

Studio는 프리셋을 DSH에 등록해 반영합니다. 하지만 세션이 실제로 받는 내용은 설치된 Studio 빌드, 프로필의 플러그인, DSH가 서브에이전트를 구성하는 방식에 따라서도 달라집니다. 이 부록은 실행 중인 세션에서 결과를 확인하는 에이전트 스킬을 제공합니다. 에이전트가 지정한 서브에이전트를 시작하고, 읽기 전용 스크립트가 저장된 프리셋과 각 세션이 받은 내용을 비교합니다.

## 확인하는 항목

저장된 프리셋(`<프로필>/studio-data/presets.json`)이 기준입니다. 스크립트는 이 값을 현재 세션과, 그 세션이 시작한 모든 서브에이전트의 세션 기록과 비교합니다.

| 묶음 | 확인 내용 |
|---|---|
| 빌드 | 프로필에 설치된 Studio 버전, 그리고 세션이 그 버전으로 실행됐을 수 있는지 |
| 프리셋 | 반영되어 있는지, 세션 시작 후에 바뀌지 않았는지 |
| 부모 세션 | 도구, 편집한 도구·인자 설명, 실행 기본값, 추가 지침, persona, 편집한 사용 지침 |
| 각 서브에이전트 | 역할, 시작 방식(Fork / Fresh), 모델, DSH가 적용한 Tool Filter와 역할의 방식으로 계산한 Tool Filter의 비교, 도구 목록(부모 − Tool Filter), 뺀 도구의 사용 지침이 사라졌는지 |

항목마다 PASS, FAIL, UNKNOWN과 이유가 나옵니다. 스크립트는 아무것도 쓰지 않습니다.

> 세션 기록은 DSH의 내부 저장 형식이고 공개 인터페이스가 아닙니다. 이후 DSH 버전에서 바뀔 수 있으며, 그 경우 스크립트는 추측하지 않고 UNKNOWN으로 보고합니다.

## 스킬 설치

스킬은 [preset-check](preset-check/) 폴더입니다. `SKILL.md`(에이전트용 지침)와 `check-preset.mjs`(스크립트)가 들어 있습니다. 이 폴더를 DSH가 읽는 스킬 디렉터리에 복사합니다.

```sh
# 이 레포지토리를 clone한 위치에서
mkdir -p ~/.dsh/skills
cp -R docs/appendix/preset-check ~/.dsh/skills/dsh-studio-preset-check
```

DSH는 새 스킬을 다시 시작하지 않아도 인식합니다. 특정 프로젝트에서만 쓰려면 `<프로젝트>/.dsh/skills/`, 또는 `~/.agents/skills/`에 두어도 됩니다.

필요한 것: Node.js 22.15 이상(또는 `zstd` 명령), DSH 홈(기본 `~/.dsh`)을 읽을 수 있는 권한.

## 사용 방법

1. Studio에서 시험할 역할을 프리셋에 만듭니다. 예:

   | 역할 ID | 시작 방식 | 서브에이전트 Tool Filter |
   |---|---|---|
   | `worker` | 부모 대화 이어받기 (Fork) | 프리셋 기본값 사용 |
   | `reviewer` | 새 대화 (Fresh) | 기본값에 추가: `write`, `edit`, `bash` |

2. 저장하고 DSH에 반영한 뒤, 그 프리셋으로 **새** 세션을 엽니다. 세션은 앱이 시작될 때 불러온 Studio 빌드로 실행됩니다. 새 Studio 빌드를 설치했다면 먼저 앱을 다시 시작하세요.
3. 에이전트에게 요청합니다. 예: *"dsh-studio-preset-check 스킬로 worker와 reviewer 역할을 시작해서 결과를 보고해줘."*

에이전트는 역할마다 정해진 읽기 전용 작업을 맡기고, 보고를 모두 받은 뒤 스크립트를 실행해 모든 항목을 표로 답합니다.

스크립트를 직접 실행할 수도 있습니다.

```sh
node ~/.dsh/skills/dsh-studio-preset-check/check-preset.mjs <세션 ID> --profile desktop
```

`dsh web`이면 `--profile web`, 결과를 데이터로 받으려면 `--json`을 붙입니다. 실패한 항목이 있으면 종료 코드가 1입니다.

## 결과 읽기

| 결과 | 뜻 | 할 일 |
|---|---|---|
| `build` UNKNOWN 또는 FAIL | 세션이 다른 Studio 빌드로 실행됐을 수 있음 | 앱을 다시 시작하고 새 세션에서 확인 |
| `preset` UNKNOWN: 세션 시작 후 다시 반영됨 | 기대값이 세션이 쓴 프리셋이 아니라 현재 프리셋 기준 | 새 세션에서 확인 |
| `Tool Filter` FAIL | DSH가 역할의 방식과 다른 목록을 적용함 | Studio에서 역할의 Tool Filter 선택을 확인하고 저장·반영 |
| `tools` FAIL, `extra …` | 프리셋이 선택하지 않았거나 뺀 도구가 세션에 들어감 | 프로필의 플러그인과 프리셋의 도구 선택 확인 |
| `… instructions removed` FAIL | 뺀 도구의 사용 지침이 서브에이전트 프롬프트에 남음 | 스크립트 출력과 함께 버그로 제보 |

**추가 지침**에 쓴 문장은 뺀 도구를 언급하더라도 서브에이전트에 그대로 들어갑니다. 의도된 동작입니다.
