# DSH Studio 소개

[English](introduction.md) | 한국어

DSH Studio는 DeepSeek Harness(DSH)의 **에이전트 프리셋**을 화면에서 만들고 고치는 플러그인입니다. YAML을 직접 쓰지 않고, 에이전트가 받을 지침·도구·플러그인 설정·서브에이전트 역할을 한곳에서 정한 뒤 DSH에 반영합니다. 자세한 화면 설명은 [사용 가이드](guide.ko.md)에 있습니다.

## 무엇을 해결하나

DSH 프리셋은 플러그인 목록과 설정을 담은 선언입니다. 강력하지만 다음이 어렵습니다.

- 어떤 도구와 지침이 모델에 전달되는지 미리 보기
- 기본 프리셋을 조금만 바꾸면서 나머지는 DSH 기본값을 그대로 따르게 하기
- 도구 설명이나 실행 기본값을 프리셋마다 다르게 하기
- 서브에이전트를 역할별로 나누어 맡기기

Studio는 이것을 화면으로 다루고, 결과를 Studio 소유의 DSH 프리셋으로 등록합니다. DSH 기본 프리셋이나 프로필의 패키지 목록은 건드리지 않습니다.

## 프리셋은 어떻게 만들어지나

모든 Studio 프리셋은 **Studio Master** 위에 변경분만 얹어 만듭니다.

```text
DSH standard 프리셋 (실행 중인 DSH가 선언한 그대로)
  + Studio가 더하는 플러그인   read_batch, spill-policy, tool-cordis, plugin-manager
  + 직접 추가한 플러그인       실행 설정 → 플러그인 추가
  ───────────────────────────────────────────────
  = Studio Master (읽기 전용 기준)

Studio Master
  − 포함하지 않을 플러그인     실행 설정 → 포함할 플러그인
  + Config 덮어쓰기            바꾼 필드만
  + 도구 선택·도구 설명 편집   프롬프트·도구
  + 추가 지침, persona
  + subagent_role과 역할       서브에이전트 (standard의 subagent 도구를 대체)
  ───────────────────────────────────────────────
  = 내 프리셋 → DSH에 반영 → 새 세션에서 선택
```

Studio Master가 DSH `standard`를 따르므로, DSH를 업데이트하면 기준도 함께 바뀝니다. 화면의 각 플러그인에는 출처 배지(`standard`, `Studio`, `추가함`)가 붙어 어디서 온 것인지 알 수 있습니다.

## 모델이 실제로 받는 것

세션에서 모델이 받는 내용은 종류에 따라 들어가는 시점이 다릅니다. **프롬프트 미리보기**는 이 중 세 가지를 나눠 보여 줍니다.

| 종류 | 들어가는 시점 | 예 | 미리보기 |
|---|---|---|---|
| 시스템 프롬프트 | 매 요청 | persona, 도구 사용 지침, 추가 지침, 계획 모드 안내 | **시스템 프롬프트·도구** |
| 도구 스키마 | 매 요청 | read, bash, subagent_role | **시스템 프롬프트·도구** |
| 런타임 컨텍스트 | 매 요청, 시스템 프롬프트 뒤 | 권한·샌드박스 상태, 서브에이전트 위임 안내 | **런타임 컨텍스트** |
| 턴 시작 메시지 | 턴 시작 | AGENTS.md 지침, 현재 시각, 스킬 목록 | **턴 시작 내용** (예시와 설정 편집) |
| 도구 결과 뒤 안내 | 파일을 읽거나 고친 뒤 | 하위 폴더의 AGENTS.md | 나오지 않음 |
| 대화 정리 | 한도에 가까울 때 | 자동 압축 요약, 긴 도구 결과 줄이기 | 나오지 않음 |

AGENTS.md 지침이나 현재 시각은 시스템 프롬프트가 아니라 턴마다 대화 메시지로 들어갑니다. 그래서 내용은 실행할 때 파일과 시각에서 만들어지고, Studio에서는 그 내용을 정하는 설정(`maxBytes`, 지침 파일 후보, `timeZone` 등)을 바꿉니다.

## 기본값, 덮어쓰기, 제외

실행 설정의 각 플러그인은 세 상태 중 하나입니다.

| 상태 | 저장되는 것 | 결과 |
|---|---|---|
| **기본값** | 없음 | 플러그인이 DSH 기본값으로 포함됩니다 |
| **덮어쓰기** | 바꾼 필드만 | 포함되며 그 필드만 바뀝니다. 덮어쓰기를 끄면 기본값으로 돌아갑니다 |
| **제외** | 제외 목록에 ID | 플러그인이 이 프리셋에서 빠집니다 |

예를 들어 자동 압축을 다루는 방법은 두 가지입니다.

- `compaction-basic`의 `auto`를 `false`로 **덮어쓰기**: 압축 기능과 `/compact`는 남고 자동 실행만 꺼집니다.
- `compaction-basic`을 **제외**: 압축 기능이 빠지고, 이에 의존하는 `/compact`도 함께 빠집니다.

덮어쓰기를 끄는 것은 "끄기"가 아니라 "기본값으로 돌아가기"입니다. 기능을 빼려면 포함 목록에서 체크를 끕니다.

## 도구는 시작 구성일 뿐 차단 목록이 아님

프리셋에서 고른 도구는 세션의 **시작 도구 구성**입니다.

- 고르지 않은 도구는 세션이 시작될 때 보이지 않습니다.
- 세션이 시작된 뒤 다른 플러그인이 새 이름으로 등록하는 도구는 DSH 기본 흐름대로 쓸 수 있습니다.
- 예약 작업처럼 DSH가 세션마다 직접 붙이는 도구는 프리셋 도구 목록에 나오지 않지만, 켜져 있으면 세션에서 쓸 수 있습니다.
- 고른 도구를 제공하는 플러그인을 빼면 반영 단계에서 막아, 도구가 몰래 사라지지 않게 합니다.

DSH의 승인·파일 접근·서브에이전트 제한 같은 안전 정책은 Studio가 바꾸지 않습니다.

## Optimized

Studio에는 코딩 에이전트용 기본 프리셋 **Optimized**가 들어 있습니다.

- 시작 구성을 도구 27개로 고정합니다. 다른 플러그인을 설치해도 선택이 늘어나지 않습니다.
- 서브에이전트 도구를 `subagent_role` 하나로 합치고, 같은 지침을 물려받되 위임·질문·`judge`·`pixie_loop`은 빼고 일하는 **Worker** 역할을 넣었습니다.
- 독립적인 읽기를 묶고, 백그라운드 작업을 폴링하지 않고 기다리며, 확인 범위를 작업에 맞추도록 지침과 도구 설명을 다듬었습니다.
- 대화 압축, AGENTS.md 지침, 스킬 목록 같은 `standard`의 기능은 그대로 포함됩니다.

편집하지 않은 Optimized는 Studio를 시작할 때마다 다시 조정됩니다. 바로 편집하거나 복사해서 사용할 수 있으며, **기본값으로 복구**를 사용하면 Studio 기본값으로 되돌릴 수 있습니다. 방법은 [Optimized를 내 작업에 맞게 고치기](guide.ko.md#optimized를-내-작업에-맞게-고치기)를 참고하세요.

## 바뀌었을 때 Studio가 하는 일

| 상황 | Studio의 동작 |
|---|---|
| DSH 업데이트, 플러그인 설치·삭제로 도구나 플러그인이 바뀜 | 다음 시작 때 목록 위에 변경 안내(`+` 추가, `-` 제거, `~` 형식 변경). **확인하고 정리**를 누르기 전에는 프리셋을 바꾸지 않습니다 |
| 정리를 확인함 | 사라진 항목의 선택·설명·덮어쓰기만 지우고, 반영된 프리셋은 **다시 반영 필요**로 표시합니다 |
| 수집이 일부 실패함 | 이전 기준을 그대로 두고, 아무것도 지우지 않습니다 |
| 이전 버전이 기능을 빠뜨리고 반영함 | 카드에 **기능 누락**을 표시하고, **복구**로 확인 후 다시 반영합니다 |
| 이미 실행 중인 세션 | 프리셋 편집은 자동으로 적용되지 않습니다. 새 세션부터 적용됩니다 |

## Studio가 하지 않는 것

- DSH 본체나 다른 프리셋을 수정하지 않습니다.
- 패키지를 설치하지 않습니다. 플러그인은 프로필에 먼저 설치해야 합니다.
- 압축 알고리즘이나 도구 동작을 바꾸지 않습니다. 설명과 설정만 바꿉니다.
- 실행 중인 세션을 다시 구성하지 않습니다.
